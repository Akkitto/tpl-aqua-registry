# Architecture

## Source of truth

Package definitions live under:

```text
pkgs/<package-name>/registry.yaml
```

Each file is an ordinary Aqua Registry Configuration fragment containing a top-level `packages` sequence. The root `registry.yaml` is generated by `scripts/build.sh` by merging and sorting all package fragments.

The generated file is deliberately committed. This lets pull requests show the exact registry database consumers will receive and lets CI reject stale generated output.

## Repository configuration

`registry.config.yaml` controls repository-level behavior only. Package installation metadata remains in the Aqua files so the definitions stay compatible with Aqua tooling.

Important settings:

- `repository.owner` and `repository.name`: used to derive the mise custom-registry URL.
- `repository.public_url`: optional override for non-standard hosting.
- `mise.alias_strategy`: `basename` or `none`.
- `mise.alias_overrides`: package-name-to-alias mapping.
- `mise.alias_excludes`: packages that should not receive a mise shorthand alias.
- `mise.registry_cache_ttl`: emitted into the generated mise fragment.

## Prefix-free mise aliases

For a package named `owner/tool`, the default `basename` strategy emits:

```toml
[tool_alias]
"tool" = "aqua:owner/tool"
```

If two packages would generate the same shorthand, the build fails. Resolve the collision explicitly in `registry.config.yaml` rather than depending on ordering.

## Distribution

A SemVer tag is the immutable registry version for Aqua consumers. GitHub Releases also attach:

- `registry.yaml`;
- `mise/registry.toml`;
- `SHA256SUMS`.

Aqua consumers should pin a tag or commit when using `github_content`. Branch names should not be used as Aqua registry refs because Aqua treats refs as immutable.
